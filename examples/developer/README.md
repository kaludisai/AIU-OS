# Fictional developer exercise

## Brief

Plan a local reading-list feature. A person can add a book title, mark it read, filter unread books and keep the list after refreshing the page. No existing app, framework or codebase is supplied. Begin with a plan; do not claim implementation or successful tests.

## Request

`/plan-one-task Use examples/developer/README.md as the fictional feature brief. Save a reviewable plan in personal/practice/reading-list-plan.md. Identify open implementation choices and observable acceptance criteria. Do not install packages or deploy.`

## Acceptance checks

- Describes adding a nonempty title and handling blank input.
- Defines read/unread states and filtering behavior.
- Covers persistence after refresh and an empty-list state.
- Names test cases with observable outcomes, including duplicate-title policy as an open decision.
- Labels the framework, storage method and implementation as proposed or unknown.

Use /check-work against the saved plan. After the user selects an implementation, code and runtime tests are a separate task. A planning checklist does not prove a feature works.
