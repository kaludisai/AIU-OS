# refine-workflow

1. Read the actual output, review and user feedback.

2. Identify one reusable principle behind the miss.

3. If no correction is warranted, say so; do not invent work.

4. Propose the smallest change to the relevant source, route or skill and explain why.

5. Obtain the user's acceptance before treating it as durable guidance; an explicit request to apply a clearly specified change already supplies that acceptance.

6. Preserve user edits and unrelated behavior.

7. When editing a skill entry, update its matching .claude and .agents copy identically.

8. Record the approved change using templates/feedback.md in the selected project or personal/feedback/.

9. Rerun the affected task if authorized and available; otherwise label the retest pending.

10. Compare the observed result against the original failed criterion.

11. A saved coaching note alone is not a successful improvement.

12. Never retrain the model, grant new access or publish changes implicitly.
